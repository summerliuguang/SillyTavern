# SillyTavern 使用说明

> 本机私有部署的 AI 角色扮演 / 角色对话前端，模型经家庭网关 LiteGate 中转。
> 部署位置：`~/web-projects/SillyTavern` · 管理中心分类：「AI 语音」→ SillyTavern
> 更新时间：2026-09-10

---

## 一、这是干什么用的？

SillyTavern（简称 ST）是一个**和 AI 角色对话、玩文字角色扮演（RP）的本地网页界面**。它本身不带 AI 模型，负责提供界面、角色管理、记忆、世界观设定等能力，把对话内容发给后端大模型。可以拿来：

- 和自建角色聊天（历史人物、小说角色、原创人设都行）
- 文字冒险 / 互动小说（AI 扮演旁白和 NPC）
- 多角色群聊（一个 AI 同时扮演多个角色）
- 给回复配音朗读（已接入小米 MiMo 语音合成）

**本套部署的特点：**

| 项 | 说明 |
|---|---|
| 访问地址 | https://192.168.5.15:29009 （局域网内手机/电脑均可，浏览器提示证书警告属正常，点"高级→继续访问"即可） |
| 聊天模型 | LiteGate 免费渠道：`nemotron-3-ultra`（550B，默认，质量高、带思考）和 `nemotron-3-super`（120B，更快）。免费，但高峰期可能排队变慢 |
| 语音 | MiMo TTS（限时免费），默认音色 Chloe，可用 `/speak` 朗读任意文本 |
| 隐私 | 全部数据（角色、聊天记录、设置）只存在本机 `data/default-user/` 目录，不上传任何第三方 |
| 用量 | 走 LiteGate 网关，可在 LiteGate 管理页（29007）按 sillytavern 密钥查调用记录 |

## 二、快速上手（3 分钟开聊）

1. 管理中心 → 「AI 语音」→ SillyTavern（首次访问接受证书警告）
2. 页面打开后会**自动连接 LiteGate**（右上角插头图标变正常、API 面板显示绿点 Valid）。如果没连上：点插头图标 → 点 **Connect** 按钮
3. 欢迎页有一句 Assistant 欢迎语，直接在**底部输入框**打字，回车或点纸飞机按钮发送
4. 等 AI 回复（免费模型首次响应约 2~5 秒，思考型回复更久），就可以聊起来了

想换角色？见「四、角色卡」；想朗读？见「八、语音朗读」。

## 四、角色卡（Character Card）

### 是什么？

角色卡 = 一个"AI 扮演的人"的完整档案。社区通用格式是 **Tavern 卡（PNG 图片内嵌人设数据）**：表面看是一张角色头像图，里面藏着名字、性格、说话方式、开场白等。导入后 AI 就"变成"这个角色。

### 从哪来？

- 社区分享站：如 Chub、character card 分享论坛等，下载 `.png` / `.json` 角色卡文件（搜 "character card" / "Tavern card"；注意甄别内容安全性）
- 自己做（见下）
- 中文站也有大量现成卡；拿到 png 直接导入即可

### 怎么导入？

把 png/json 文件**直接拖到网页的角色列表区**，或：人像卡图标（Character Management）→ **Import Character**（导入按钮）→ 选文件。导入后点角色头像即开新聊天。

### 怎么创建？（人像卡面板 → Create Character）

| 字段 | 填什么 | 建议 |
|---|---|---|
| Name | 角色名 | 聊天中显示的名字 |
| Avatar | 头像图片 | 随意，png/jpg |
| Description（描述） | 角色的完整设定：身份、外貌、经历、说话习惯 | **最重要**。写"她是……她说话……她讨厌……"式的陈述句，越具体 AI 演得越像 |
| Personality（性格） | 一句话概括性格 | 简短关键词即可 |
| Scenario（场景） | 你们相遇的情境 | 如"深夜的便利店，她是夜班店员" |
| First Message（第一条消息） | 角色**主动说的第一句话** | 强烈建议写，并带上动作描写（用 `*星号*` 包裹动作是 RP 惯例），开场决定整个故事的走向 |
| Alternate Greetings | 备用开场白 | 可存多个开场，聊天里点 `<` 切换 |
| Example Dialogue（对话示例） | 2~3 轮示范对话 | 教 AI 说话的语气和格式，模仿效果最好 |
| Character's Note | 角色私有备注 | 少用 |
| Character Book | 角色专属世界书 | 进阶用法，见「七」 |

填完 Create 保存。之后随时可以点角色旁的编辑按钮回来改设定——**改设定不影响已有聊天，只影响之后的回复**。

### 管理角色

角色列表里每个角色旁有更多菜单：改名、删除（会连聊天记录一起删，谨慎）、导出（把角色连同设定导出成 png 分享给别人）。

## 六、如何对话（进阶技巧）

1. **引导而非审问**：AI 的回复质量很大程度取决于你的输入。用动作+对话混合写法效果好：
   > *我推门进来，抖了抖伞上的雨水* 这么晚还没打烊？
2. **控制剧情走向**：直接在消息里描述你想发生的事，或用 OOC（Out of Character）括号备注，如 `（OOC：接下来我们把场景切换到第二天早上）`
3. **不满意就 Swipe**：点 `>` 重摇，多摇几次挑最好的；或点铅笔手改 AI 的回复再继续
4. **Continue（继续）**：回复被打断/太短时，更多菜单里点 Continue 让 AI 接着写
5. **Impersonate（替我写）**：不知道怎么回时，让 AI 替你的角色写一条，再手动发送
6. **常用斜杠命令**（输入 `/` 有菜单）：`/speak 文本` 朗读、`/sys 文本` 以系统身份注入一条信息、`/help` 查看全部命令
7. **聊天记录管理**：一个角色可以有多个独立聊天（切角色时在角色菜单里看历史聊天列表）；重要节点可建分支（fork）跑不同剧情线

## 七、世界书（World Info / Lorebook）

### 是什么？

世界书 = **按关键词触发的设定库**。世界书里存一条条"词条"，每个词条绑定触发关键词：当聊天内容中出现关键词时，对应设定才被注入给 AI；没提到就不注入。这样可以在不撑爆上下文的前提下，维护一个庞大的世界观（城市、门派、上百个角色…）。

类比：角色卡是"主演"的剧本，世界书是剧组的资料库——演到谁，资料才递上去。

### 怎么建？

1. 点顶栏**地图书图标**（World Info）→ 输入书名 → Create（或 Import 导入别人做好的世界书 json）
2. **New Entry** 新建词条，核心字段：

| 字段 | 说明 |
|---|---|
| Title / Memo | 词条标题（备注用） |
| Keys（关键词） | 触发词，英文逗号分隔，如 `魔法学院, 学院`。支持正则（进阶） |
| Content（内容） | 触发后注入给 AI 的设定文本，如"魔法学院位于王都北郊，只招收觉醒者，院长是……" |
| Constant（绿灯💡） | **常驻模式**：不管有没有触发词，每轮都注入。用于最核心的世界规则（消耗上下文，慎用） |
| 非常驻（蓝灯🔗） | 默认：出现关键词才注入，省 token |
| Order（顺序） | 同时触发多条时，数字大的越靠前（越重要） |
| Depth（深度） | 注入到对话的多近位置，一般默认即可 |

3. **绑定到角色**：Character Management → 编辑角色 → Character Book，可以为单个角色挂专属世界书（如"她的家族成员表"）；全局设定集（如"整个大陆的地图"）在世界书面板保持激活即可作用于所有聊天。

### 使用建议

- 词条内容用**陈述句**写设定，别写成对话
- 关键词选"对话中真的会出现"的词，一个词条可设多个同义触发词
- 先从三五条常驻核心设定 + 若干触发词条起步，逐步扩充

## 八、记忆机制（重点）

LLM 没有真正的记忆，"记忆"= 每次请求把相关内容塞进上下文窗口。ST 提供了从轻到重四层方案，**可以叠加使用**：

### 1. 聊天记录（短期记忆，自动）

最近的对话本身就随请求发给 AI。本部署上下文设为 **16K token**，大约能装下最近几千字的对话；超出窗口后，最早的对话开始"淡忘"（不是删除，文件还在，只是 AI 看不到了）。

### 2. 作者注释 Author's Note（手动固定记忆）

聊天输入框上方的**便签图标** 📝，打开 Author's Note 面板：

- 写什么：需要 AI **始终知道**的一两句话——当前剧情阶段、你的要求、文风指令（如"用轻小说风格描写，每段不超过三句"）
- 注入位置默认在对话靠后处（ influence 最强），可调 Depth
- 适合：手动维护"上一幕结束于……现在……"的剧情锚点

### 3. 总结记忆 Summarize / Chat Memory（自动长期记忆，推荐）

扩展面板（立方体图标）→ **Chat Memory（Summarize）**：

- 原理：定期让主模型把聊天**总结成一段摘要**，摘要随每轮请求注入——AI 因此"记得"很久之前的剧情
- 关键设置：
  - **Record the summary as notifications?** 无关紧要
  - **Update every N messages**：每 N 条消息自动更新一次摘要（建议 10~20）
  - Injection Position：默认（Author's Note 位置）即可
  - Source：默认 main（即用 LiteGate 当前模型来总结）
- 也可以随时输入 `/summarize` 手动触发
- 摘要会随剧情推进自动改写，属于"滚动的剧情梗概"

### 4. 世界书当记忆库（手动长期设定）

聊出重要事实后（AI 的家族背景定下来了、主角获得了一件神器），手动把它写进世界书词条——这是最稳定、最不占上下文的记忆方式，代价是要手动维护。

### 5. 向量存储 Vector Storage（语义检索，进阶）

扩展面板 → Vector Storage：把全部历史消息做**语义向量索引**，每轮自动检索最相关的旧片段注入，实现"想起几周前说过的话"。

> ⚠️ 本部署暂不建议开：它需要一个**嵌入（embedding）模型**，LiteGate 目前没有嵌入渠道。可选浏览器本地模式（transformers，首次要下载模型、较慢）。真有需要说一声，给 LiteGate 配一个嵌入模型渠道即可启用。

### 推荐组合

| 用法 | 方案 |
|---|---|
| 轻度闲聊 | 什么都不用动 |
| 长篇连续剧情 | 总结扩展（自动摘要）+ 作者注释写剧情锚点 |
| 维护固定世界观 | 世界书 + 总结扩展 |
| 超长跑团（几个月的存档） | 世界书手动维护设定 + 总结 + （配好嵌入后）向量检索 |

## 九、语音朗读（MiMo TTS）

- **朗读任意文本**：输入 `/speak 要读的话`
- **朗读 AI 回复**：消息操作菜单（…）里有朗读按钮；也可以在 TTS 扩展里开自动朗读
- **换音色**：扩展面板 → TTS → OpenAI Compatible → Available Voices 改音色列表：`mimo_default、冰糖、茉莉、苏打、白桦、Mia、Chloe、Milo、Dean`（当前 TTS 限时免费）
- **给角色固定音色**：TTS 面板的 Voice Map 表格里，把角色名对应的音色选好（默认都走 Chloe）
- 注意：语音合成走 ST 服务端 → LiteGate，手机端一样可用；目前**没有麦克风语音输入**（ST 本版无语音识别），想要的话需另装第三方 STT 扩展

## 九·五、Live2D 立绘（已安装）

角色以**会动的 Live2D 模型**显示在聊天旁：待机呼吸/眨眼、鼠标跟随、点击互动、TTS 说话时口型开合。

- **内置模型**（已放在 `data/default-user/assets/live2d/`）：`Hiyori`（日织）、`Haru`、`Wanko`，均为 Live2D 官方免费样例，仅限个人用途
- **演示角色**：已创建角色「日织」并绑定 Hiyori 模型——点开她的聊天即可看到
- **给其他角色绑定**：扩展面板（立方体图标）→ Live2D → Character 下拉选角色 → Live2d Model 选模型；分配后在 Model Settings 里可调大小（scale）和位置（x/y 滑杆），也可以直接**鼠标拖拽**模型，松手自动记住位置
- **添加新模型**：从社区下载 Live2D 模型（文件夹里必须有 `*.model3.json`），整个文件夹放进 `data/default-user/assets/live2d/`，刷新即可出现在下拉里
- **互动**：模型支持点击区域（如点身体触发动作/消息）；"Auto-send interaction" 开启后点击会自动发给 AI
- 注意：模型渲染在浏览器里，**手机端可用但较耗电**；模型默认画在聊天层后面，若被遮挡可在 Model Settings 里调小/挪位，或换更窄的聊天窗口

## 十、模型与参数速查

| 项 | 当前值 | 在哪调 |
|---|---|---|
| 模型 | nemotron-3-ultra（默认）/ nemotron-3-super | API Connections 面板 → Available Models 下拉 |
| 上下文窗口 | 16384 token | AI Response Configuration → Context Size |
| 单次回复上限 | 1024 token（含"思考"消耗） | AI Response Configuration → Response Length |
| 温度等采样参数 | 默认 | AI Response Configuration |

- **ultra 是思考型模型**：回复前会先"Thought for N seconds"（可折叠查看思考过程），思考也消耗回复长度——如果发现回复被截断或只剩思考没正文，把 Response Length 调大到 2000+，或换 super 模型
- **自动连接**已开启：页面打开即连 LiteGate；异常掉线时点插头图标 → Connect 重连
- 想加模型：在 LiteGate 管理页配好渠道后，编辑 sillytavern 密钥的白名单把模型加进去，ST 里刷新模型列表即可

## 十二、常见问题（FAQ）

| 现象 | 原因与处理 |
|---|---|
| 打不开，502 Bad Gateway | ST 正在启动（每次启动要重新编译前端，约 30 秒），等半分钟刷新即可 |
| 证书警告 | 自签证书，正常。点"高级 → 继续访问" |
| 发消息报错 / 插头图标带感叹号 | 连接断了：点插头 → Connect 重连（自动连接已开，一般不用管） |
| 回复很慢 | 免费渠道高峰期排队。可换 super 模型（快很多），或错峰使用 |
| 回复中途断了 / 只有思考没有正文 | 回复长度不够：Response Length 调大到 2000+ |
| AI 忘了之前的设定 | 见「八、记忆机制」：写进作者注释/世界书，或开总结扩展 |
| 想重新开始剧情 | 聊天列表新建聊天（设定保留、历史清零）；或从某条消息建分支 |
| 手机能用吗 | 能。同一地址，界面自适应竖屏 |
